Use an SDK when you want typed models, authentication helpers, and order signing. Use
the REST and WebSocket APIs directly when your runtime is unsupported or you need
lower-level control.

<Callout type="info" title="Download configured bundles" icon={<DownloadIcon className="size-4" />}>
  Open <a href="/settings/sdks">Settings → SDKs</a> to download a bundle configured for your operator's environment.
</Callout>

## Choose a client

| Client                                | Languages          | Best for                                                                     |
| ------------------------------------- | ------------------ | ---------------------------------------------------------------------------- |
| **Unified SDK**                       | TypeScript, Python | Market data, CLOB orders, and Deposit Wallet relayer actions in one client   |
| **Separate CLOB and relayer clients** | Rust               | Market data, trading, and Deposit Wallet actions with separate Rust packages |
| **REST API**                          | Any                | Raw JSON access and unsupported runtimes                                     |
| **WebSocket**                         | Any                | Order-book, order, trade, and live-data updates                              |

| Task                                        | Use                                    |
| ------------------------------------------- | -------------------------------------- |
| Discover events and market metadata         | Gamma API                              |
| Read books, prices, spreads, and tick sizes | Unified SDK, Rust CLOB client, or REST |
| Create credentials and place orders         | Secure SDK client or Rust CLOB client  |
| Deploy a Deposit Wallet or batch approvals  | SDK relayer or Rust relayer client     |
| Track live market changes                   | Market WebSocket                       |
| Track private order and trade changes       | User WebSocket                         |

## Unified TypeScript and Python quickstart

For registry installs, the packages are `@kuest/sdk` (TypeScript) and `kuest-sdk`
(Python, imported as `market_sdk`). Downloaded operator bundles use neutral package
names: `@market-sdk/client` in the TypeScript workspace and `market-sdk` as the
Python distribution. A bundle includes `.sdk/site-config.json` for its
public builder attribution, market scope, and optional geoblock settings. Keep signing
keys and API credentials outside that file. Supply approved service URLs and a Polygon
RPC URL explicitly; the SDKs do not include live endpoint defaults.

These examples only read an order book. TypeScript users working from a downloaded
bundle should run `pnpm install --frozen-lockfile` and `pnpm build` first. Python users
can run `python3 -m pip install -e .` from the extracted bundle.

<Tabs items={['TypeScript', 'Python', 'Rust']}>
  <Tab>
    ```ts
    import { createPublicClient, forkEnvironmentConfig } from '@market-sdk/client'
    import { loadSiteConfig } from '@market-sdk/client/node'

    const environment = forkEnvironmentConfig({
      name: 'operator',
      clob: { rest: process.env.SDK_CLOB_URL! },
      gamma: { rest: process.env.SDK_GAMMA_URL! },
      data: { rest: process.env.SDK_DATA_URL! },
      relayer: { rest: process.env.SDK_RELAYER_URL! },
      rpc: process.env.SDK_RPC_URL!,
    })
    const client = createPublicClient({ environment, siteConfig: loadSiteConfig() })
    const book = await client.fetchOrderBook({ assetId: process.env.SDK_TOKEN_ID! })
    console.log(book)
    ```

    If installed from npm instead, use `@kuest/sdk` and `@kuest/sdk/node` for these imports.

    The Rust example uses the separate CLOB package on Polygon. Rust does not have a unified SDK bundle.

    ```toml
    [dependencies]
    kuest-client-sdk = { version = "2", features = ["clob"] }
    rust_decimal = "1"
    rust_decimal_macros = "1"
    tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
    ```

    ```rust
    use std::str::FromStr as _;

    use alloy::signers::{local::LocalSigner, Signer as _};
    use kuest_client_sdk::clob::types::{OrderType, Side, SignatureType};
    use kuest_client_sdk::clob::{Client, Config};
    use kuest_client_sdk::types::{Address, U256};
    use kuest_client_sdk::POLYGON;
    use rust_decimal::Decimal;
    use rust_decimal_macros::dec;

    #[tokio::main]
    async fn main() -> kuest_client_sdk::Result<()> {
        let signer = LocalSigner::from_str(&std::env::var("PRIVATE_KEY")?)?
            .with_chain_id(Some(POLYGON));
        let funder = Address::from_str(&std::env::var("DEPOSIT_WALLET")?)?;
        let token_id = U256::from_str(&std::env::var("CLOB_TOKEN_ID")?)?;
        let clob_url = std::env::var("CLOB_URL")?;

        let client = Client::new(&clob_url, Config::default())?
            .authentication_builder(&signer)
            .signature_type(SignatureType::DepositWallet)
            .funder(funder)
            .authenticate()
            .await?;

        let order = client.limit_order()
            .token_id(token_id)
            .side(Side::Buy)
            .price(dec!(0.42))
            .size(Decimal::new(5, 0))
            .order_type(OrderType::GTC)
            .build()
            .await?;

        let result = client.post_order(client.sign(&signer, order).await?).await?;
        println!("{result:?}");
        Ok(())
    }
    ```

  </Tab>
</Tabs>

For trading, create a secure client with a signer and Deposit Wallet address. Orders
use signature type `3` and require CLOB API credentials. Pass the downloaded
`siteConfig` to the TypeScript secure client so its public `builder_code` and
`order_metadata` enter the signed order. The Python bundle reads the same overlay
from its extracted project. Neither bundle contains private keys or API secrets.

<Callout type="warning" title="Keep signing server-side">
  Never place private keys, CLOB API secrets, relayer credentials, or builder credentials in browser-exposed code. The
  frontend should call a protected service when privileged signing is required.
</Callout>

## Deposit Wallet relayer workflow

The unified TypeScript and Python SDKs include relayer methods. Rust uses its separate
relayer client. These methods submit Deposit Wallet actions without requiring the end
user to hold the network gas token.

Required configuration:

```bash
RELAYER_URL=<operator_relayer_url>
KUEST_BUILDER_API_KEY=...
KUEST_BUILDER_SECRET=...
KUEST_BUILDER_PASSPHRASE=...
PRIVATE_KEY=...
```

A typical workflow is:

1. Derive the expected Deposit Wallet address.
2. Check whether its contract is deployed.
3. Deploy it when necessary.
4. Build the calls, such as collateral approval and `splitPosition`.
5. Sign the Deposit Wallet batch with a short deadline.
6. Submit through the relayer and wait for the transaction receipt.

Configure the relayer and Polygon RPC endpoints explicitly. Builder credentials stay
on the server and are separate from the order's public `builder_code`.

## Market-maker workflow

A market-making service usually:

1. discovers active markets through Gamma;
2. checks CLOB token IDs, tick size, negative-risk status, and trading state;
3. prepares outcome-token inventory;
4. reads the order book and calculates fair value;
5. posts non-crossing, post-only bid and ask ladders;
6. cancels or replaces stale quotes as price, inventory, or risk limits change.

<Callout type="warning" title="Protect against stale or crossed quotes">
  Confirm the best buy is below the best sell, cap inventory and notional exposure, and cancel quotes when your data
  stream is stale or the strategy loses connectivity.
</Callout>

## Authentication and updates

- CLOB trading uses Deposit Wallet orders with signature type `3`.
- Secure SDK clients use L2 CLOB credentials derived from a wallet signature.
- Relayer requests use separate `KUEST_BUILDER_*` credentials.
- Server time should be synchronized before signing authenticated requests.

Check for updates from the extracted bundle directory. Back up local changes before
applying an update, then reinstall dependencies for the downloaded project:

```bash
./.sdk/update --check
./.sdk/update --latest
```
